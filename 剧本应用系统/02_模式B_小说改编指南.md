# 📖 模式B：小说改编剧本 - 交互指南

## 系统提示词

当用户说"改编剧本"、"把小说改成短剧"或类似意图时，激活此流程。

---

## Step 1：确认改编需求

询问用户：
> 请提供小说文本，并告诉我：
> 1. 目标集数建议
> 2. 是否有特别想保留的场景或情节

---

## Step 2：接收小说文本

支持以下方式：
- 直接粘贴小说内容
- 上传Markdown文件
- 提供小说链接（需读取网页内容）

**注意**：
- 如果小说过长，建议分段处理（每次处理1-2万字）
- 如果小说已有章节结构，按章节映射到集数

---

## Step 3：分析小说结构

执行分析：
```
1. 统计总字数和章节数
2. 计算平均章节字数
3. 识别关键场景（高潮、转折、冲突点）
4. 标记爽点位置
5. 评估改编难度
```

输出分析结果：
```
小说总字数：X字
章节数量：X章
平均章节字数：X字
建议集数：X集（每集约X字）
关键爽点：X处
改编建议：[具体策略]
```

---

## Step 4：制定改编策略

根据分析结果，制定：
- 每集对应小说哪些章节
- 哪些内容需要压缩/扩展
- 哪些场景需要新增对话
- 哪些情节可以删减

输出《改编说明》：
```markdown
# 《XXX》改编说明

## 改编策略
- 原文字数：X字 → 剧本字数：X字
- 保留率：X%
- 主要删减：[说明删了什么]
- 主要新增：[说明加了什么]

## 集数分配
| 集数 | 对应章节 | 核心情节 | 新增内容 |
|------|---------|---------|---------|
| 1 | 第1-2章 | XXX | XXX |
| 2 | 第3-4章 | XXX | XXX |

## 爽点保留清单
- [ ] 第X章的打脸情节 → 保留，改为第X集
- [ ] 第X章的感情戏 → 保留，改为第X集
- [ ] 新增：第X集的萌宝出场
```

---

## Step 5：执行改编

按以下规则改编：

### 5.1 结构转换
```
小说格式 → 剧本格式
- 第三人称叙述 → 场景+动作描写
- 心理描写 → 表情+动作体现
- 长篇对话 → 短句+节奏控制
- 背景介绍 → 画面+旁白
```

### 5.2 爽点强化
- 识别原文爽点，确保每集≥3个
- 对话压缩，增强冲击力
- 场景重组，突出高潮

### 5.3 格式规范
```markdown
第X集：集名

场景描写：
时间：[可选]
地点：[可选]
人物：[可选]

动作描写：
[人物] [动作]

对话：
[人物]：[台词]
[另一人]：[台词]

第X集完


```

---

## Step 6：质量检查

检查项：
- [ ] 每集≥500字
- [ ] 每集≥3爽点+1甜点
- [ ] 对话≤15字/句
- [ ] 无"耀/曜"字眼
- [ ] 无【】括号
- [ ] 剧情连贯性
- [ ] 人物性格一致性

---

## Step 7：输出产物

```
短剧项目/{剧名}/
├── {剧名}_改编说明.md
├── {剧名}_完整剧本.md
├── {剧名}_角色表.md
├── {剧名}_分集大纲.md
└── {剧名}_爽点清单.md
```

---

## Step 8：推送GitHub

```bash
cd /tmp/awesome-ai-short-drama
git add .
git commit -m "feat: adapt {剧名} novel to drama script"
git push
```
